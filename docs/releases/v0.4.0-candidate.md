# VeritasMed 0.4.0 development candidate

Date: 2026-09-22. Status: implemented and demonstrated locally; answer-quality targets not met.
Branch: `feature/veritasmed-agent-v0.4`. The measured runtime is `a945a8f`; later delivery changes
package the saved evaluation and documentation. No stable tag, GitHub Release or remote push is implied.

## What can be demonstrated

The Agent breaks a question into source-bound components with exact quotations and explicit gaps.
Generation and targeted repair share that outline. The interface exposes complete, partial and
insufficient coverage, expandable evidence and source navigation; the model check is not an accuracy score.

The labelled Guided examples work without a backend. A fresh Windows installation also completed a
real `qwen3.5:9b` fastMRI+ answer in 57.48 seconds, preserving the supported findings and the gap in
diagnostic-accuracy evidence. The demo corpus consists of three authored summaries. See the
[walkthrough and screenshots](../demo.md) and [README](../../README.md) for installation.

## Measured result

| Run | Strict passes | Unsupported additions | Execution failures | Mean time |
|---|---:|---:|---:|---:|
| Focus A, six development questions | 5/6 | 1 | 0 | 95.0 s |
| Focus B, same six questions, independent run | 4/6 | 1 | 1 | 119.4 s |
| Separate full development run | 9/15 | 3 | 1 | 84.8 s |

The full run was paused and resumed with its first six completed answers unchanged. No output was
selected across runs. There were two missing required qualifiers and only 12/13 answerable questions
with all necessary evidence retained. Compared with v0.3's 10/15 strict passes and 13/13 evidence
coverage, this is **not an overall answer-quality improvement**. The unchanged target of at least
13/15 and zero unsupported additions was missed. The 35-question test split remains unused.

The main failures are development-versus-validation population scope, an unsupported refusal
rationale, a lost second study, a missing null-result contrast and invalid structured output.
The model check does not reliably catch these errors. Repeated quotations and an occasional internal
evidence label in a gap also remain presentation defects. Codex adjudicated the retained outputs
against frozen source passages; there was no independent clinician review.

## Local execution record

The fresh demo path used Python 3.12.7, the 163-package CPU lock, `npm ci` and cached model downloads.
The separate benchmark used CPU BGE-M3 embeddings and CUDA reranking with local Ollama. Offline Python
behavior checks passed (173 cases), as did relevant static checks and the earlier frontend build/browser
walkthrough. Hosted CI has not run for this unpublished candidate. Docker, MiMo and macOS/Linux were
not exercised. The API has a 300-second deadline; focus B's 381.2-second CLI failure would time out
earlier through the UI. No latency or reliability guarantee is made for arbitrary questions.
