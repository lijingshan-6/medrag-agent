## 已定位的问题与改动

- 第二来源实际已召回。旧分组重排将广义综述排到前面，五个名额被截断后，
  研究身份匹配才执行，已看不到目标研究。改为在完整候选列表上匹配问题点名的研究，
  然后对匹配研究的片段重排。没有按题号、论文 ID 或标准答案过滤。
- 原数字补全只检查数字出现，不能保护样本用于开发、校准、测试还是验证。
  对原文明示的单一角色增加窄范围保护；角色丢失的陈述被拒绝，必要信息通过完整原句恢复。
  多角色或语义歧义仍需逐句复核，程序不声称解决所有来源范围问题。
- 所选原句包含完整对照时，保留其 `whereas/while` 等后半句；方法步骤也纳入必要细节，
  避免数值齐全却没有解释方法。缺失内容从绑定原句补回，不生成新数值。
- 缺口默认只命名未建立的结果或比较，不自由发挥研究背景。
- 结构化步骤使用 Ollama JSON 输出模式，边界提纲改为直接输出；去除生成与检查提示中
  重复的整段证据。格式限制只约束输出形式，正确边界仍以实际答案对原文评阅。
  接口依据：[Ollama Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs)、
  [Thinking](https://docs.ollama.com/capabilities/thinking)。

## 运行记录

检索定位记录保存在本地 `.benchmark-runtime/v04_retrieval_trace.log`。
探针一六题均返回了答案，但双研究问题仍有来源遗漏。定位发现：第二篇已经召回，
把所有研究卡片一次交给模型匹配时，模型只选择了第一篇。探针二改为每个检索子问题
单独匹配，009/011 的开发样本角色、032 的不显著对照及两道边界题的技术失败得到改善，
但 018 在两篇原文均已保留的情况下仍漏掉第一篇的方法与验证结果。

探针二还揭示两类问题：数字全部出现不代表主体正确，009 省去了“医师在 AI 辅助下”；
检查模型也会漏回第二个组件的检查项，或额外要求原文没有给出的损失函数与数据划分。
这两轮是调试记录，不作为最终评测，也不从中挑选成功答案。

因此探针三采用逐篇整理和检查、全局唯一原句 ID、完整关键原句呈现，并通过 JSON Schema
要求检查结果包含每个组件。关键数字、方法的原句会比摘要更长，这是保留主体、样本角色、
比较对象的明确取舍。语义检查仍可判错；Schema 只约束结构。
两轮旧实现和原始输出分别保存在本地 `v04_repair_probe1_code` / `v04_repair_probe2_code`
及对应 `*_raw.json`、日志中；正式交付时另附归档，原候选报告不覆盖。

探针三保留了 018 的全部方法/结果原句，但逐篇提纲仍看到了另一篇的问题，因此制造了
互相矛盾的缺口。探针四只传检索子查询后，011 的问题消失；018 又暴露出关键词查询丢失
完整任务的缺陷：遗漏方法步骤，并把“报告验证结果”擅自解读为“必须给出定量或临床结果”。
032 也出现了只复述设计、没有解释因果限制的退步。这些输出都保留，不能计为修复成功。

探针五进一步由来源匹配阶段生成完整的单研究子问题，保留原问题要求的各方面；
定性验证按原文报告，不额外要求未被问到的数字或临床效果。允许从明示设计得出的限制说明，
要求把解释和数字拆为不同陈述；数字原句保留不能删除这一解释。
生成器不再自由改写缺口，因为它曾把没有被问到的临床结果加入拒答。

探针五修复了 032 的设计解释，但 018 仍失败：匹配研究时看过论文内容再扩写子问题，

探针六将完整单研究问题提前到路由阶段，只根据用户问题生成；检索后的来源匹配只认定研究，
