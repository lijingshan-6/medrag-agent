# 研究基线决定：固定使用 Flash

日期：2026-09-23。状态：当前生效。

用户决定后续以 OpenHub 的 **`deepseek-v4.1-flash`** 作为 Agent 研究基线，原因是
Pro 的 token 成本过高，不适合持续迭代。本决定替代此前“不考虑预算”的实验前提和
“下一阶段固定使用 Pro”的建议。这里记录的是用户的成本取舍，没有推算或核验网关账单。

## 具体采用什么

- 路由、研究匹配、证据组织、回答生成和自检均使用 Flash，不默认混入 Pro 审核或回退。
- 保持现有完整 Agent 流程；继续使用 thinking、`high` 推理强度、每次调用 32,768 输出
  token 上限和流式传输。这个上限不是实际消耗量，本次没有通过缩小预算来降低回答要求。
- 研究脚本默认只运行 Flash，最多同时处理三个问题。Pro 保留为历史对照；只有明确选择
  双模型对比时才运行，不再随每轮开发自动重跑。
- Ollama `qwen3.5:9b` 仍是已有本地演示路径；未指定后端时的代码默认值仍为 MiMo。
  当前研究配置通过 `.env` 显式选择 OpenHub/Flash，不能把这三件事混为一个默认值。

配置与运行入口见 [演示及研究配置](../demo.md#flash-research-profile)。
OpenHub ID 只是网关提供的名称，不能独立确认底层模型权重。

## 如何理解现有结果

[Pro/Flash 对比报告](../agent-model-comparison-report.md) 和全部原始答案继续保留。
选择 Flash 不代表它已经与 Pro 等效，也不改变任何失败判定。Qwen 的历史修复成绩
同样不能写成 Flash 的成绩。模型自检通过不是独立的正确率评估。

黄金题集、证据要求和评分口径保持不变。继续用 15 道开发题改进；35 道测试题仍保留，
等实现方案固定后再使用。当前版本仍是 v0.4 开发候选版，本决定不代表已经发布。

## 下一轮先改什么

按以下顺序处理已保存答案暴露出的共同 Agent 问题，固定 Flash 观察改动效果：

1. **来源匹配**：允许 `LGR5-targeted` 等自然表述中的描述性后缀，保留真正的实体限制，
   避免正确论文在模型阅读前被过滤。
2. **问题范围与缺口**：只要求用户实际问到的内容；定性验证不能因为没提供额外数字而被
   判作没有验证。部分回答时只说明真正缺少的部分。
3. **答案一致性**：自检同时读取正文和最终缺口，避免正文引用了结果，末尾又声称没有结果。
4. **可读性**：正文给出有依据的简洁解释，完整引文放在可展开证据里，同时保留数字、
   比较对象、人群角色和因果边界。

作出本决定时，这些修复尚未实施。先查看对应失败是否改善，再运行完整开发集；保留失败及重复运行，
不挑选最好的一次替换原结果。下一轮结果进入新的报告，不能覆盖已有对比实验。

本决定只集中维护模型选择及当前优先级。文档分工见 [文档索引](../README.md)。
